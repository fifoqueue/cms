# 댓글

상위 문서: [AGENTS.md](../../AGENTS.md)

- Authenticated moderators bypass plugin comment checkers and start approved; `comment.beforeSave` still runs. Notification recipients are fixed by core: `comment.notification` may change only subject and text, not `to`.

- Password-protected entries require the existing `x-cms-unlock` proofs for comment reads and submissions. Locked entries do not render comments; recent-comment widgets exclude protected entries.
- Public comment submissions accept an optional bearer session. A verified user's `userId`, name and email come from the profile, never the submitted identity. Discussion `requireLogin` rejects anonymous submissions; moderators still use the moderation capability.
- Discussion `showName`, `showEmail`, and `showWebsite` independently remove anonymous identity fields (all default on). Disabling names requires a nonempty `defaultName` (max 100); disabled submitted values are ignored before validation. Authenticated comments always use the profile name/email and no submitted website. Missing anonymous email is stored as an empty string, never grants known-commenter status or a commenter proof, and has no avatar. Moderators with resolved `comments.moderate` bypass built-in approval rules, including word lists and link limits. Captcha, rate limits, honeypot, protected/open/reply checks and plugin verdicts still apply; submitted role/capability fields never grant this exemption.
- Public comment pages expose only the three form-field flags in `fields`. SvelteKit enhances the comment action without a document navigation or whole-page invalidation: it refreshes the returned thread page/count/pending receipt, preserves failed drafts/reply context, prevents concurrent submissions, and resets captcha tokens after every attempt. Ordinary forms keep the POST/redirect fallback. Remembered preferences contain only enabled fields; preference/proof cookies remain explicit opt-in.
- `GET /api/v1/comments` returns `viewer` (name only), `requireLogin`, and `ownPending`. `x-cms-comment-pending` carries a signed, entry-bound, 24-hour receipt; only that receipt's currently pending comment is shown. Spam/trash and other pending comments remain hidden. Comment responses use `private, no-store`.
- Submission returns `{ status, comment, page, pendingProof, commenterProof }`; `page` identifies the top-level thread's page, including replies. The web keeps `cpage` and failed reply context, and stores receipts in httpOnly cookies. Commenter name/email/website and the signed one-year commenter proof are remembered only after an explicit checkbox opt-in; later submissions carry it in `x-cms-commenter-proof`. `known` moderation accepts that proof only while its referenced comment remains approved for the same email; the unsigned preference cookie is never identity. All session, unlock, pending-receipt and commenter-preference responses use `private, no-store`.
- Discussion `showAvatars` defaults off; when enabled `avatarDefault` selects the Gravatar fallback style. Public DTOs contain only a signed same-origin avatar proxy URL, never an email or public email digest. Admin comment DTOs include `parentAuthor` for reply context; moderation supports a `contentId` filter.

- Comments are core: plain-text bodies, threaded up to the configured depth, paginated by top-level comment. Public DTOs never contain email addresses. `contents.comment_count` counts approved comments and is updated in the same transaction as every status change.
- Public entry pages let viewers with `comments.moderate` approve, unapprove, trash and permanently delete comments in place. A separate `management` projection contains only display fields, is paged per entry (`mstatus`/`mpage`, 20 rows), and is never sent to non-moderators or for locked entries. These responses are `private, no-store`. The `moderateComment` action resolves the entry from the request address and passes `contentId` to the bulk API, which checks every comment belongs to that entry before mutating anything. Permanent deletion requires `confirm=delete`; enhanced actions preserve the draft, and ordinary forms show scoped failures or an allowlisted `commentNotice` after redirect. A failed refresh never changes a successful mutation into a retryable failure.
- Submission order: validation, rate limit/captcha, honeypot (accepted silently, stored nowhere), open check (discussion on, type supports comments, entry allows them, age limit), reply check, block/hold words and link limit, moderation mode (`manual`, `known`, `auto`), `comment.beforeSave` filter (only `body` and `status` are taken), insert, hooks, notification mail (queued). Held and spam comments both answer `pending`.
- Moderators (`comments.moderate`) approve, unapprove, mark spam, trash, delete, edit and reply (replying approves the parent). Deleting a comment moves its replies up. Spam and trash older than 30 days are purged by a task.
