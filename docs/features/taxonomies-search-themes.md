# 분류·검색·선언형 테마

상위 문서: [AGENTS.md](../../AGENTS.md)

Plugin taxonomies use namespaced keys (`plugin:<id>:<key>`) and the same
term-management service as category/tag. Disabling a declaration hides its
taxonomy without deleting terms or assignments. Existing custom keys remain
valid; the additive column-width migration accommodates namespaced keys.

Plugins can contribute validated template/part data through
`themeContributions.register`. Public theme reads and previews merge active
contributions while preserving saved administrator overrides. Invalid merged
themes are discarded, and disabling the plugin restores core theme output
without changing persisted customizations. Plugin pattern groups are available
from `/api/v1/admin/patterns/contributions` for editor insertion.

- Categories are hierarchical; tags are flat. Admins manage terms and assign them to content. Public category/tag archives and search use the same published-content reader, filtering before pagination and computing totals with the same criteria.
- Content input accepts `categoryIds` and `tagIds`. Content list queries accept `search`, `category` (slug), and `tag` (slug), in addition to existing pagination/type filters. Admin queries additionally accept `status`.
- Public search uses `/?q=...` and includes published posts and pages. Category/tag archives likewise include every assigned published content type. Existing root content URLs such as `/search`, `/category`, and `/tag` remain valid and editable; only `admin` is reserved.
- Themes are **WordPress-style block themes** (`packages/sdk/src/themes.ts`, `blocks.ts`): a `.zip` with `theme.json` (id, name, version, author, `settings.color.palette` with the required slugs `base`/`surface`/`contrast`/`muted`/`accent`/`border`, `settings.typography.fontFamilies`, `settings.layout.contentSize`/`wideSize`, `settings.scrollToTop` (entry pages show a back-to-top button with reading progress; default `true`), `settings.color.alternatePalette` and `settings.colorScheme`, `styles` and `templateParts`), `templates/<name>.json`, `parts/<slug>.json`, an optional `style.css` and an optional `screenshot.png`/`screenshot.webp` (≤ 512 KB, checked by content, stored in settings, served to admins at `GET /api/v1/admin/themes/:id/screenshot`; built-ins show a palette preview). A theme is data, never code: templates and parts are trees of core blocks (`BLOCKS`: group, columns, template-part, site-title, navigation, search, scheme-toggle, widget-area, post-title/meta/content/excerpt/featured-image/terms/fields, comments, breadcrumbs, query with post-template/no-results/pagination, query-title, heading, paragraph, site-logo, post-navigation, buttons/button, social-links/social-link, latest-posts, categories, tag-cloud, archives, loginout, image, cover, media-text, post-author, read-more, page-list, latest-comments, calendar, …), each attribute declared with type and default and validated by `parseBlocks` (depth 16, 1000 nodes). Link attributes (`LINK`) accept site paths, `http(s):`, `mailto:` and fragments only; image attributes (`MEDIA_IMAGE`) accept media-library paths (`/media/…`) only.
- Block data is loaded per page, for the template that page renders (and the parts it includes) only, in parallel (`lib/server/theme-queries.ts`): independent `query` and `latest-posts` lists, term lists, months (`GET /api/v1/months`), previous/next entries (`GET /api/v1/adjacent?contentId=`), the page tree (public `parentId`, null while the parent is unpublished, trashed or password-protected; locked pages are not listed; pages and calendar months are read page by page up to 2,000 items), recent comments (`GET /api/v1/comments/recent?limit=`, approved on unprotected public entries), the authors post-author blocks show (the entry's, or each listed post's in loops; `GET /api/v1/authors/:slug` with `avatarUrl` while avatars are shown) and a calendar month (UTC, weeks starting on Settings → General's first weekday, with links to the nearest months with posts from `GET /api/v1/month-neighbours?year=&month=`). Results a page shares with the layout (lists, terms, months, pages, recent comments) are reused within the request; months and comments by the limit they were requested with. The site layout loads only the `404` template's data, for error pages; pages reuse what it loaded instead of asking again. Block data never uses the visitor's session. Content pages start the path lookup and slots before the layout finishes.
- Templates follow the WordPress hierarchy (`lib/theme/template.ts`): `front-page`; `single-<type>-<slug>` → `single-<type>` → `single` → `singular`; `page-<slug>` → `page` → `singular`; `category-<slug>` → `category` → `archive` (tag, author alike); `archive-<type>`; `date`; `home`; `search`; `404`; always ending in `index` (required). `query` blocks inherit the page query by default. With `inherit: false`, each block selects published content by type, category, tag, author and count; the frontend loads these on the server and deduplicates selections. A theme is limited to 32 independent query blocks.
- `style.css` is applied inside `@scope (.cms-site) to (.cms-auth)`, excluding theme-independent authentication screens. Public pages and the site editor's canvases share `ThemeStylesheet`; authentication shells reuse the admin design tokens and fonts in both color modes. `cssProblem` refuses markup, backslash escapes, `@import`, `url()`, `image-set()` and other resource loads, and unbalanced braces outside comments/strings (so it cannot leave the scope). Fonts are font stacks only (no font files).
- Appearance → Themes uploads/upgrades zips (2 MB, unpacked by `infra/zip-theme-archive.ts` with fflate; per-file and total size limits), activates, previews and removes themes. Built-in themes (`canvas` default, `journal`) cannot be replaced or removed. Canvas is a clean, bright layout with post lists and a sidebar column when widgets exist. Journal (`domain/theme/journal-theme.ts`, hooks `theme-journal-*`) is a dark magazine-style blog: a header with logo, centred menu, light/dark toggle and search panel (`search` with `panel`), a mobile off-canvas menu, three-column 16:9 card grids inside a 75rem container, singular entries with an overlaid image header, right sidebar, previous/next links and boxed comments; its body font stack names Nanum Gothic first (system Korean faces until an administrator adds that family as a site font). A stored active theme or site-editor changes for a removed built-in id (`editorial`, `magazine`) are ignored on read, so the site falls back to Canvas; a theme installed later under such an id starts without the old changes.
- Color schemes: `settings.color.alternatePalette` (the same slugs in the opposite scheme) with `settings.colorScheme` `{ auto, toggle }`. The public layout adds head CSS that swaps the alternate palette in (`:root[data-cms-scheme=alternate]`, or the `prefers-color-scheme` media query while `auto` and no choice is stored) and a blocking script that restores the visitor's choice from `localStorage` (`cms-color-scheme`) before the first paint. The `scheme-toggle` block (and the off-canvas menu) offers the switch only when `toggle` is set. The site editor edits the main palette only.
- Site fonts (Appearance → Editor → Styles; `GET/PUT /api/v1/admin/fonts`, one `fonts` setting for every theme): each family (`siteFontSchema`) loads from an external stylesheet (`https:` only, no credentials, no spaces/quotes/brackets/backslashes — e.g. a Google Fonts CSS2 address with `display=swap`) or from font files (an `https:` address or a media-library `/media/…` path ending in `.woff2`/`.woff`/`.ttf`/`.otf`) with weight, style and `font-display` (default `swap`) per face. Site fonts join the theme's font families (a site font with a theme family's slug replaces it), so Styles can choose them for body and headings; a removed font falls back to the theme's choice. The public theme DTO's `fonts` lists only the site fonts the effective body/heading stacks name (a theme stack such as `"Nanum Gothic", sans-serif` picks up a site font of that family), and the layout emits a `<link rel="stylesheet">` or `@font-face` rules for those only (`SiteFonts.svelte`). The media library accepts WOFF2/WOFF/TTF/OTF by signature and stores them unprocessed, served with `font/*` types. The app sets no `font-src`/`style-src` on public pages; a CSP added by a proxy must allow the configured font origins.
- Appearance → Editor (site editor) changes templates, template parts and global styles (palette colors, fonts, size, line height, radius) of any theme; changes are stored beside the theme (`themes.customizations` setting) and can be reset, and new hierarchy templates (e.g. `category-news`) can be added. Public theme DTOs carry the effective theme only, no management state.
- Signed-in visitors see a WordPress-style toolbar on the public site (dashboard, edit site, new, edit this entry, account). The public layout reads only the session cookie for it (via `getAll`) and passes only `{ name, slug, role, capabilities }` (`slug` is the public author slug, used to recognise the viewer's own entries; capabilities are resolved by the API on every request); never email, ids or tokens. Such responses are never cached.
- Theme selection changes presentation only. Content, taxonomy archives, search, and every plugin slot must work with every theme and with no active plugins.
- Reference behavior: [WordPress categories and tags](https://make.wordpress.org/support/user-manual/categories-and-tags/), [global settings and styles](https://developer.wordpress.org/themes/global-settings-and-styles/), and [theme management](https://wordpress.org/documentation/article/appearance-themes-screen/).
