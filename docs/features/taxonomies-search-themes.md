# 분류·검색·선언형 테마

상위 문서: [AGENTS.md](../../AGENTS.md)

플러그인 분류는 네임스페이스가 붙은 키(`plugin:<id>:<key>`)를 사용하며 카테고리/태그와 같은 용어 관리 서비스를 씁니다. 선언을 비활성화하면 용어와 할당을 삭제하지 않고 해당 분류만 숨깁니다. 기존 사용자 지정 키는 계속 유효하며, 컬럼 너비를 늘리는 추가형 마이그레이션이 네임스페이스 키를 수용합니다.

플러그인은 `themeContributions.register`로 검증된 템플릿/파트 데이터를 제공할 수 있습니다. 공개 테마 조회와 미리보기는 활성 기여분을 병합하면서 저장된 관리자 재정의를 유지합니다. 병합 결과가 올바르지 않은 테마는 폐기되며, 플러그인을 비활성화하면 저장된 사용자 지정은 그대로 둔 채 코어 테마 출력으로 돌아갑니다. 플러그인 패턴 그룹은 편집기 삽입용으로 `/api/v1/admin/patterns/contributions`에서 제공됩니다.

- 카테고리는 계층형이고 태그는 평면형입니다. 관리자는 용어를 관리하고 콘텐츠에 할당합니다. 공개 카테고리/태그 아카이브와 검색은 같은 게시 콘텐츠 리더를 사용하며, 페이지 나누기 전에 필터링하고 같은 기준으로 합계를 계산합니다.
- 콘텐츠 입력은 `categoryIds`와 `tagIds`를 받습니다. 콘텐츠 목록 쿼리는 기존 페이지 나누기/유형 필터에 더해 `search`, `category`(슬러그), `tag`(슬러그)를 받습니다. 관리자 쿼리는 추가로 `status`를 받습니다.
- 공개 검색은 `/?q=...`를 사용하며 게시된 글과 페이지를 포함합니다. 카테고리/태그 아카이브도 할당된 모든 게시 콘텐츠 유형을 포함합니다. `/search`, `/category`, `/tag` 같은 기존 루트 콘텐츠 URL도 계속 유효합니다. `admin`, `api`, `_app` 루트와 SDK 고유주소 규약의 아카이브/자산 하위 경로 및 생성 문서 경로는 예약됩니다. `/preview/theme/style.css`는 예약된 `/preview/` 아래 두 세그먼트를 쓰므로 `/preview/[token]`과도 겹치지 않는 웹 전용 테마 스타일시트입니다.
- 테마는 **WordPress 방식의 블록 테마**입니다(`packages/sdk/src/themes.ts`, `blocks.ts`). `theme.json`(id, name, version, author, 필수 슬러그 `base`/`surface`/`contrast`/`muted`/`accent`/`border`를 가진 `settings.color.palette`, `settings.typography.fontFamilies`, `settings.layout.contentSize`/`wideSize`, `settings.scrollToTop`(항목 페이지에 읽기 진행률을 보여 주는 맨 위로 버튼을 표시하며 기본값은 `true`), `settings.color.alternatePalette`와 `settings.colorScheme`, `styles`, `templateParts`), `templates/<name>.json`, `parts/<slug>.json`, 선택 사항인 `style.css`, 선택 사항인 `screenshot.png`/`screenshot.webp`(512KB 이하, 내용으로 검사하고 설정에 저장하며 관리자에게 `GET /api/v1/admin/themes/:id/screenshot`으로 제공합니다. 내장 테마는 팔레트 미리보기를 보여 줍니다)를 담은 `.zip` 파일입니다. 테마는 코드가 아니라 데이터입니다. 템플릿과 파트는 코어 블록(`BLOCKS`: group, columns, template-part, site-title, navigation, search, scheme-toggle, widget-area, post-title/meta/content/excerpt/featured-image/terms/fields, comments, breadcrumbs, post-template/no-results/pagination을 가진 query, query-title, heading, paragraph, site-logo, post-navigation, buttons/button, social-links/social-link, latest-posts, categories, tag-cloud, archives, loginout, image, cover, media-text, post-author, read-more, page-list, latest-comments, calendar, …)의 트리이며, 각 속성은 타입과 기본값을 선언하고 `parseBlocks`(깊이 16, 노드 1000개)로 검증합니다. 링크 속성(`LINK`)은 사이트 경로, `http(s):`, `mailto:`, 프래그먼트만 허용하고, 이미지 속성(`MEDIA_IMAGE`)은 미디어 라이브러리 경로(`/media/…`)만 허용합니다.
- 블록 데이터는 페이지마다 렌더링할 템플릿과 전이적으로 포함된 파트에 필요한 것만 병렬로 불러옵니다(`lib/server/theme-queries.ts`). 목록, 용어, 월, 페이지 트리, 최근 댓글 등 공유 결과는 요청 안에서 재사용합니다. 사이트 레이아웃은 `404`와 그 밖의 오류에 대한 `index` fallback의 데이터 요구를 합쳐 중복 없이 병렬로 읽고 한 번만 직렬화합니다. 두 오류가 같은 템플릿을 선택하면 템플릿과 파트도 한 번만 보냅니다. 페이지는 이 결과를 재사용하며 블록 데이터는 방문자의 세션을 사용하지 않습니다. 콘텐츠 페이지는 레이아웃이 끝나기 전에 경로 조회와 슬롯을 시작하고, 정적 첫 페이지의 슬롯은 `frontPagePath`로 읽은 콘텐츠 ID를 명시합니다.
- 템플릿은 WordPress 계층 구조를 따릅니다(`lib/theme/template.ts`): `front-page`; `single-<type>-<slug>` → `single-<type>` → `single` → `singular`; `page-<slug>` → `page` → `singular`; `category-<slug>` → `category` → `archive`(태그, 글쓴이도 같습니다); `archive-<type>`; `date`; `home`; `search`; `404`; 항상 `index`(필수)로 끝납니다. `query` 블록은 기본적으로 페이지 쿼리를 상속합니다. `inherit: false`이면 각 블록이 유형, 카테고리, 태그, 글쓴이, 개수로 게시 콘텐츠를 선택하며, 프런트엔드가 이를 서버에서 불러오고 선택 항목의 중복을 제거합니다. 테마는 독립적인 query 블록을 32개까지 가질 수 있습니다.
- `style.css`는 `@scope (.cms-site) to (.cms-auth)` 안에서 적용되므로 테마와 무관한 인증 화면은 제외됩니다. 공개 페이지와 사이트 편집기의 캔버스는 `ThemeStylesheet`를 공유하며, 인증 셸은 두 색상 모드 모두에서 관리자 디자인 토큰과 글꼴을 재사용합니다. `cssProblem`은 마크업, 백슬래시 이스케이프, `@import`, `url()`, `image-set()` 및 기타 리소스 로드와, 주석/문자열 밖의 짝이 맞지 않는 중괄호를 거부합니다(스코프를 벗어날 수 없도록 하기 위해서입니다). 글꼴은 글꼴 스택만 가능합니다(글꼴 파일 없음).
- 테마 → 테마에서 zip을 업로드/업그레이드(2MB, `infra/zip-theme-archive.ts`가 fflate로 압축을 풀며 파일별·전체 크기 제한이 있습니다)하고 테마를 활성화, 미리보기, 삭제합니다. 내장 테마(기본값 `canvas`, `journal`)는 교체하거나 삭제할 수 없습니다. Canvas는 글 목록과, 위젯이 있을 때 사이드바 열을 갖춘 깔끔하고 밝은 레이아웃입니다. Journal(`domain/theme/journal-theme.ts`, 훅 `theme-journal-*`)은 어두운 매거진 스타일의 블로그입니다. 로고, 가운데 정렬 메뉴, 라이트/다크 전환, 검색 패널(`panel`을 가진 `search`)이 있는 헤더, 모바일 오프캔버스 메뉴, 75rem 컨테이너 안의 3열 16:9 카드 그리드, 이미지 헤더를 겹친 단일 항목, 오른쪽 사이드바, 이전/다음 링크, 박스형 댓글을 갖추고 있으며, 본문 글꼴 스택은 Nanum Gothic을 가장 앞에 둡니다(관리자가 그 글꼴을 사이트 글꼴로 추가하기 전까지는 시스템 한국어 글꼴). 삭제된 내장 id(`editorial`, `magazine`)에 대해 저장된 활성 테마나 사이트 편집기 변경은 읽을 때 무시되어 사이트가 Canvas로 대체되며, 이후 그런 id로 설치한 테마는 이전 변경 없이 시작합니다.
- 색상 구성표: `settings.color.alternatePalette`(반대 구성표의 동일한 슬러그)와 `settings.colorScheme` `{ auto, toggle }`. 공개 레이아웃은 대체 팔레트로 바꾸는 head CSS(`:root[data-cms-scheme=alternate]`, 또는 `auto`이고 저장된 선택이 없을 때는 `prefers-color-scheme` 미디어 쿼리)와, 첫 페인트 전에 `localStorage`(`cms-color-scheme`)에서 방문자의 선택을 복원하는 블로킹 스크립트를 추가합니다. `scheme-toggle` 블록(과 오프캔버스 메뉴)은 `toggle`이 설정된 경우에만 전환 기능을 제공합니다. 사이트 편집기는 기본 팔레트만 편집합니다.
- 사이트 글꼴(테마 → 편집기 → 스타일; `GET/PUT /api/v1/admin/fonts`, 모든 테마가 하나의 `fonts` 설정을 공유): 각 글꼴 패밀리(`siteFontSchema`)는 외부 스타일시트(`https:`만 허용하며 자격 증명, 공백/따옴표/대괄호/백슬래시 불가 — 예: `display=swap`이 있는 Google Fonts CSS2 주소) 또는 글꼴 파일(`https:` 주소 또는 `.woff2`/`.woff`/`.ttf`/`.otf`로 끝나는 미디어 라이브러리 `/media/…` 경로)에서 불러오며, 글꼴 면마다 굵기, 스타일, `font-display`(기본값 `swap`)를 지정합니다. 사이트 글꼴은 테마의 글꼴 패밀리에 합쳐지므로(테마 패밀리와 슬러그가 같은 사이트 글꼴이 그것을 대체합니다) 스타일에서 본문과 제목용으로 선택할 수 있고, 삭제된 글꼴은 테마의 선택으로 대체됩니다. 공개 테마 DTO의 `fonts`에는 실제 적용되는 본문/제목 스택이 이름을 든 사이트 글꼴만 나열되며(`"Nanum Gothic", sans-serif` 같은 테마 스택은 해당 패밀리의 사이트 글꼴을 가져옵니다), 레이아웃은 그 글꼴에 대해서만 `<link rel="stylesheet">` 또는 `@font-face` 규칙을 출력합니다(`SiteFonts.svelte`). 미디어 라이브러리는 시그니처로 WOFF2/WOFF/TTF/OTF를 받아 가공 없이 저장하고 `font/*` 타입으로 제공합니다. 앱은 공개 페이지에 `font-src`/`style-src`를 설정하지 않으므로, 프록시가 추가하는 CSP는 설정된 글꼴 출처를 허용해야 합니다.
- 테마 → 편집기(사이트 편집기)는 모든 테마의 템플릿, 템플릿 파트, 전역 스타일(팔레트 색상, 글꼴, 크기, 줄 높이, 모서리 반경)을 변경합니다. 변경 사항은 테마 옆에(`themes.customizations` 설정) 저장되고 초기화할 수 있으며, 새로운 계층 템플릿(예: `category-news`)을 추가할 수 있습니다. 공개 테마 DTO에는 실제 적용되는 테마만 담기고 관리 상태는 담기지 않습니다.
- 로그인한 방문자는 공개 사이트에서 WordPress 방식의 툴바(대시보드, 사이트 편집, 새로 만들기, 이 항목 편집, 계정)를 봅니다. 공개 레이아웃은 이를 위해 세션 쿠키만(`getAll`로) 읽고 `{ name, slug, role, capabilities }`만 전달합니다(`slug`는 공개 글쓴이 슬러그로 보는 사람 본인의 항목을 알아보는 데 쓰이며, 권한은 매 요청마다 API가 해석합니다). 이메일, id, 토큰은 절대 전달하지 않습니다. 이런 응답은 절대 캐시되지 않습니다.
- 테마 선택은 표현만 바꿉니다. 콘텐츠, 분류 아카이브, 검색, 모든 플러그인 슬롯은 어떤 테마에서도, 활성 플러그인이 없어도 동작해야 합니다.
