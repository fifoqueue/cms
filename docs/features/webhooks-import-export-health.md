# 웹훅·가져오기/내보내기·사이트 상태·캐시

항목의 출처 정보는 개인정보입니다. 내보내기에는 해당 행위자가 대상인 경우에 한해 생성/수정 IP와 사용자 에이전트, 그리고 대상의 리비전/자동 저장 출처가 포함됩니다. 개인정보 삭제 처리와 사용자 삭제는 이러한 출처와 행위자 참조를 지우며, 대상이 작성한 항목에 대한 다른 행위자의 출처 정보는 지우지 않습니다. 그 외의 경우에는 이러한 값을 해당 항목/리비전이 삭제될 때까지 보관합니다. WXR과 웹훅 페이로드에는 출처 데이터가 포함되지 않습니다.

상위 문서: [AGENTS.md](../../AGENTS.md)

사이트 상태는 하나의 레지스트리로 코어 점검과 플러그인 점검을 실행합니다. 코어 점검은 코어 전용 `registerCore` 경로로 등록되어 직접 실행되며 오류가 그대로 전파됩니다(보고서 요청이 실패합니다). 플러그인 점검이 실패하면 다른 결과를 가리지 않고 `detail: ['check failed']`를 가진 심각 항목을 생성합니다. 플러그인 항목 키는 `plugin:<id>:<key>`를 사용하며, 관리자 UI는 코어 번역 키를 요구하지 않고 이러한 동적 키를 지원해야 합니다. 비활성화된 플러그인은 더 이상 항목을 제공하지 않습니다.

상위 문서: [AGENTS.md](../../AGENTS.md)

- 설정 → 개인정보 보호에서 게시되고 보호되지 않은 정책 페이지를 선택합니다. 공개 `/api/v1/privacy`는 그 제목/경로와 댓글 쿠키 동의 설정만 노출합니다. `privacy-policy-link` 테마 블록이 이를 렌더링하며, 내장 푸터와 인증/댓글 폼에 이 링크가 포함됩니다. 체크박스를 끄면 댓글 작성자 정보를 기억하지 않고 기존 설정 쿠키는 무시합니다.
- 개인정보 큐에는 `users.manage` 권한이 필요합니다(도구 UI는 `tools.manage`도 필요). 관리자가 이메일로 내보내기/개인정보 삭제 처리를 요청하면, 당사자가 HMAC으로 서명되고 무작위 nonce를 가진 이틀짜리 링크로 확인합니다. 다이제스트만 저장하며 원자적 업데이트로 한 번만 소비됩니다. 확인에는 POST, 방문자 속도 제한/캡차, 그리고 URL에서 토큰을 제거한 뒤 제한된 httpOnly 증명 수집(최대 5건의 요청, ID로 대조)을 사용합니다. 각 폼은 비밀이 아닌 요청 ID만 담아 탭 간 토큰 바꿔치기를 막으며, 토큰은 페이지 데이터에 들어가지 않습니다. 독립 확인 페이지는 테마/플러그인 HTML 없이 사이트 언어를 사용합니다.
- 내보내기는 대상의 프로필, 댓글(저장된 IP 주소 `authorIp`와 사용자 에이전트 `authorUserAgent` 포함), API 토큰 메타데이터, 연결된 ID, 작성한 콘텐츠, 업로드한 미디어 메타데이터만 JSON으로 스트리밍합니다. 비밀번호/토큰/세션 해시나 다른 사람의 기록은 절대 포함하지 않습니다. 개인정보 삭제 처리는 확인이 필요하며, 프로필과 댓글의 신원/본문을 익명화하고(IP 주소와 사용자 에이전트는 null이 됩니다), 자격 증명/SSO를 폐기하고, 미디어 개인 메타데이터와 리비전 귀속을 지우고, 일치하는 대기/실패 스냅샷을 하나의 트랜잭션에서 제거합니다. 게시물과 업로드된 바이트는 남으며, 마지막 관리자는 익명화할 수 없습니다. 일치하는 진행 중인 전송이 있으면 끝날 때까지 개인정보 삭제 처리가 막힙니다. 공유 큐 잠금은 개인정보가 삭제 처리된 대상에 대한 뒤늦은 콜백을 막습니다.
- 이메일/웹훅 작업 본문은 `SecretBox`로 봉인되며, 시작할 때 레거시 평문 스냅샷을 업그레이드합니다. 작업은 기본적으로 7일 후 만료되며, 자격 증명 메일은 토큰과 함께, 개인정보 메일은 확인 링크와 함께 만료됩니다. 봉인된 대상 메타데이터 덕분에 개인정보 삭제 처리는 큐 메타데이터에 노출하지 않고도 개인 스냅샷을 찾을 수 있습니다. 키가 잘못되어 실패하면 현재/이전 키로 재시도할 수 있도록 복구 가능한 내부 표식과 함께 암호문을 유지하며, 사이트 상태와 로그에는 일반적인 실패 문구만 표시됩니다. 개인정보 삭제 처리는 봉인된 페이로드와 레거시 페이로드를 모두 읽고, 봉인된 스냅샷을 열 수 없거나 레거시 댓글 알림에 신뢰할 수 있는 대상 참조가 없어 검증할 수 없으면 차단합니다. 범위가 지정되지 않은 레거시 알림은 개인정보 삭제 처리가 완료되기 전에 끝나거나 만료되어야 합니다.

- 웹훅(도구 → 웹훅, `tools.manage`)은 코어 액션 이벤트를 구독하며 작업으로 전송됩니다: https로만 JSON POST를 보내고, 리디렉션은 따르지 않으며, 헤더는 `X-CMS-Signature: t=<unix>,v1=<hex HMAC-SHA256("<t>.<body>")>`이고, 백오프로 재시도하며 408/429를 제외한 4xx는 재시도를 중단합니다. 비밀 값은 생성 또는 교체 시 한 번만 표시됩니다. 구독은 코어 훅 핸들러(`HookBus.core`)입니다. 큐 등록은 플러그인 격리나 타임아웃 없이 실행되고, 실패하면 코어 오류로 기록되며 `emit`을 거부합니다. 발행자는 쓰기가 커밋된 뒤에 emit하고 기다리지 않으므로, 변경이 이미 커밋된 뒤에 원래 요청이 실패하지 않으며 전송 자체는 재시도되는 작업 큐에 남습니다. 댓글 이벤트는 댓글 작성자의 `authorIp`/`authorUserAgent` 없이 전송됩니다(모더레이터 전용 데이터이며, 웹훅에는 `tools.manage`가 필요합니다).
- 가져오기/내보내기(도구 → 가져오기 및 내보내기)는 WordPress WXR 1.2를 사용합니다. 가져오기는 16MB, 항목 10,000개, 용어 20,000개, 댓글 100,000개로 제한되며, 코어 서비스를 통해 데이터를 만들고 DTD를 거부합니다. WordPress 가져오기 도구처럼 원래 슬러그(퍼센트 인코딩 및 유니코드, NFC)를 유지하고, 같은 사이트의 이전 항목 주소(`wp:base_site_url` 아래의 `link`)를 리디렉션(`RedirectWriter`)으로 기록하고, 페이지 부모를 유지하고, `[caption]`, `[gallery]`, `[embed]`, `[audio]`, `[video]`, 단독 임베드 URL, autop 단락을 변환하고, `nav_menu_item` 메뉴를 가져오고(첫 메뉴는 비어 있는 primary 위치를 차지하며, 이름이 이미 있는 메뉴는 건너뛰므로 다시 가져와도 중복되지 않습니다), 이메일이나 로그인으로 글쓴이를 대조합니다(일치하지 않으면 가져오는 사람, 또는 `?authors=`에 따라 새 글쓴이/구독자 계정). `wp:comment_user_id`가 대조된 글쓴이에 속하는 댓글은 그 계정에 연결됩니다. 첨부 파일은 다운로드하지 않고 URL로 참조된 상태로 남으며, 결과에 대표 이미지 수와 함께 업로드할 목록이 표시됩니다. 댓글의 `wp:comment_author_IP`(유효한 IP 주소만)와 `wp:comment_agent`는 가져오고 내보냅니다. 메뉴 순서와 용어 리디렉션은 가져오지 않습니다. 내보내기는 id 커서로 콘텐츠와 댓글을 읽고 사이트를 메모리에 모으지 않고 API와 웹을 거쳐 XML을 스트리밍합니다. 항목 비밀번호는 계속 제외됩니다.
- 사이트 상태(도구 → 사이트 상태)는 사이트 주소, 이메일, 검색, 지연되거나 실패하는 작업, 실패한 전송, 실패한 플러그인, 방문자 증명을 보고합니다.
- WXR 글쓴이 목록은 1,000건으로 제한됩니다. 지원되는 항목이 참조하는 글쓴이만 고려하고, 중복은 하나의 계정을 공유하며, 계정을 100개보다 많이 만드는 요청은 쓰기 전에 거부됩니다. 클래식 변환은 항목당 입력 1MiB, 생성된 HTML 2MiB, 숏코드/자동 임베드 작업 1,000건까지 허용하며, 크기를 초과한 항목은 건너뜀으로 보고되고 미리 서식이 지정된 공백은 보존됩니다.
- Gutenberg 가져오기는 Code Block Pro의 JSON 코드 속성을 네이티브 코드 블록으로 변환합니다(지원되는 언어 별칭, 줄 번호, 기본 테마; 지원되지 않는 언어는 일반 텍스트). Simple Alert Blocks는 일치하는 변형을 가진 네이티브 콜아웃이 됩니다. 알 수 없는 블록과 잘못된 속성은 공유 콘텐츠 파서가 처리하도록 내부 HTML을 유지합니다. 아래에 설명하는 선택적 다운로드 단계는 URL만 참조하던 기존 첨부 동작을 대체합니다.
- `POST /api/v1/admin/import?downloadAttachments=true`는 동기식 첨부 파일 다운로드를 켭니다(API 기본값은 false, 도구 체크박스는 기본적으로 선택됨). 각 요청은 캐시되지 않은 다운로드를 실패한 시도를 포함해 최대 100건 시도하며, 캐시된 미디어는 이 한도를 소모하지 않습니다. 남은 첨부 파일은 “Not downloaded: re-run import”로 보고됩니다. 같은 파일을 다시 가져오면 성공한 업로드를 중복하지 않고 다운로드를 이어서 진행하므로 백그라운드 작업은 필요하지 않습니다. 기존 항목은 계속 건너뛰므로, 라이브러리 다운로드를 재개해도 이전에 가져온 항목의 외부 참조나 대표 이미지는 갱신되지 않습니다. 다운로드는 아웃바운드 정책, 파일당 10초 타임아웃, 미디어 업로드 바이트 제한을 사용합니다. MediaService가 콘텐츠 스니핑과 업로드 정책 검사를 수행합니다. 원래의 업로드 날짜 폴더는 보존되지 않으며 파일은 현재 업로드 날짜를 사용합니다. 원본 URL 매핑은 `import.media.*` 아래에 저장되며, 성공한 매핑은 이후 가져오기에서 재사용됩니다. 제목, 대체 텍스트, 캡션, 설명은 유지됩니다. 원본 URL과 크기 접미사가 붙은 URL은 라이브러리 이미지와 일치하는 파생본으로 다시 쓰이고, 공유 렌더러가 반응형 srcset을 다시 생성합니다. 대표 이미지는 `_thumbnail_id`를 사용합니다. 실패한 첨부 파일은 건너뜀 결과에 나타나고 외부 참조를 유지합니다.
- 페이지 캐시: 설정 → 읽기의 `cacheSeconds`(0 = 꺼짐). 웹은 익명 공개 GET에 `s-maxage`를 추가하며, 설정을 최대 1분에 한 번 다시 읽습니다.
- 테마 미리보기: `POST /api/v1/admin/themes/:id/preview`는 서명된 30분짜리 토큰을 반환하고, 웹은 이를 `cms_theme_preview` 쿠키에 보관하며 공개 레이아웃이 그 테마를 요청합니다. 세션, 잠금 해제, 미리보기 쿠키가 있는 방문자에 대한 응답은 캐시 가능으로 표시되지 않습니다.
