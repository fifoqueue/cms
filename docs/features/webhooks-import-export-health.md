# 웹훅·가져오기/내보내기·사이트 상태·캐시

Entry origin is personal data: export includes creation/modification IP and user
agent only where that actor is the subject, plus the subject's revision/autosave
origins. Erasure and user deletion clear those origins and actor references, not
another actor's provenance on an entry the subject authored. Otherwise these
values are retained until their entry/revision is deleted. WXR and webhook
payloads do not include origin data.

상위 문서: [AGENTS.md](../../AGENTS.md)

Site health runs core and plugin checks through one registry. Core checks
register through the core-only `registerCore` path, run directly and their
errors propagate (the report request fails). A plugin check failure produces a
critical finding with `detail: ['check failed']` without hiding other results.
Plugin finding keys use `plugin:<id>:<key>`; the
admin UI must support these dynamic keys instead of requiring core translation
keys. Disabled plugins no longer contribute findings.

- Settings → Privacy selects a published, unprotected policy page. Public `/api/v1/privacy` exposes only its title/path and the comment-cookie consent preference. The `privacy-policy-link` theme block renders it; built-in footers and authentication/comment forms include the link. Disabling the checkbox prevents remembering commenter details and ignores existing preference cookies.
- Privacy queues require `users.manage` (the Tools UI also requires `tools.manage`). Administrators request export/erasure by email; the person confirms a two-day HMAC-signed, random-nonce link. Only its digest is stored, and an atomic update consumes it once. Confirmation uses a POST, visitor rate limit/captcha, and a bounded httpOnly proof collection after removing the token from the URL (up to five requests, matched by ID). Each form carries only its non-secret request ID, preventing cross-tab token substitution; tokens never enter page data. The standalone confirmation page uses the site language without theme/plugin HTML.
- Export streams JSON with only the subject's profile, comments (including the stored IP address `authorIp` and user agent `authorUserAgent`), API-token metadata, linked identities, authored content and uploaded-media metadata. It never includes password/token/session hashes or other people's records. Erasure requires confirmation, anonymizes the profile and comment identity/body (IP address and user agent become null), revokes credentials/SSO, clears media personal metadata and revision attribution, and removes matching queued/failed snapshots in one transaction. Publications and uploaded bytes remain; the last administrator cannot be anonymized. Active matching deliveries block erasure until they finish. Shared queue locks suppress late callbacks for erased subjects.
- Email/webhook job bodies are sealed with `SecretBox`; startup upgrades legacy plaintext snapshots. Jobs expire after seven days by default, credential mail with its token, and privacy mail with its confirmation. Sealed subject metadata lets erasure find personal snapshots without exposing it in queue metadata. A wrong-key failure keeps ciphertext under an internal recoverable marker for current/previous-key retry, while site health and logs show only generic failure text. Erasure reads sealed and legacy payloads and fails closed if a sealed snapshot cannot be opened or a legacy comment notification has no reliable subject reference. Unscoped legacy notices must finish or expire before erasure completes.

- Webhooks (Tools → Webhooks, `tools.manage`) subscribe to core action events and are delivered as jobs: JSON POST to https only, no redirects, header `X-CMS-Signature: t=<unix>,v1=<hex HMAC-SHA256("<t>.<body>")>`, retried with backoff; 4xx other than 408/429 stop retries. The secret is shown once at creation or rotation. The subscription is a core hook handler (`HookBus.core`): enqueueing runs without plugin isolation or timeout, and a failure is logged as a core error and rejects `emit`. Publishers emit after their write commits and do not await, so the originating request is not failed after its change is already committed; the delivery itself stays in the retried job queue. Comment events are delivered without the commenter's `authorIp`/`authorUserAgent` (moderator-only data; webhooks need `tools.manage`).
- Import/export (Tools → Import & export) speaks WordPress WXR 1.2. Import is capped at 16MB, 10,000 entries, 20,000 terms and 100,000 comments; it creates data through the core services and refuses DTDs. Like the WordPress importer it keeps original slugs (percent-encoded and Unicode, NFC), records old same-site entry addresses (`link` under `wp:base_site_url`) as redirects (`RedirectWriter`), keeps page parents, converts `[caption]`, `[gallery]`, `[embed]`, `[audio]`, `[video]`, bare embed URLs and autop paragraphs, imports `nav_menu_item` menus (the first takes the free primary location), and matches authors by email or login (others: the importer, or new author/subscriber accounts per `?authors=`). Attachments are not downloaded: they stay referenced by URL and the result lists them, with featured-image counts, for upload. Comment `wp:comment_author_IP` (valid IP addresses only) and `wp:comment_agent` are imported and exported. Menu order and term redirects are not imported. Export reads content and comments with id cursors and streams XML through API and web without collecting the site in memory. Entry passwords remain omitted.
- Site health (Tools → Site health) reports site address, email, search, overdue or failing tasks, failed deliveries, failed plugins and visitor proof.
- WXR author lists are capped at 1,000 records. Only authors referenced by supported entries are considered, duplicates share an account, and a request creating more than 100 accounts is rejected before writes. Classic conversion permits 1 MiB input, 2 MiB generated HTML and 1,000 shortcode/automatic-embed operations per entry; oversized entries are reported as skipped, and preformatted whitespace is preserved.
- Gutenberg imports convert Code Block Pro's JSON code attributes into native code blocks (supported language aliases, line numbers, default theme; unsupported languages use plain text). Simple Alert Blocks become native callouts with their matching variant. Unknown blocks and malformed attributes retain their inner HTML for the shared content parser. The optional download stage described below supersedes the legacy URL-only attachment behavior.
- `POST /api/v1/admin/import?downloadAttachments=true` enables synchronous attachment downloads (API default false; Tools checkbox default checked). Each request attempts at most 100 uncached downloads, including failed attempts; cached media does not consume this budget. Remaining attachments are reported as “Not downloaded: re-run import”. Re-import the same file to resume downloading without duplicating successful uploads; no background job is needed. Existing entries remain skipped, so resuming library downloads does not update previously imported entries' external references or featured images. Downloads use the outbound policy, a ten-second per-file timeout and the media upload byte limit. MediaService performs content sniffing and upload-policy checks. Original upload-date folders are not preserved: files use the current upload date. Source URL mappings are stored under `import.media.*`; successful mappings are reused on subsequent imports. Title, alt, caption and description are retained. Original and dimension-suffixed URLs are rewritten to library images and matching derivatives; the shared renderer regenerates responsive srcsets. Featured images use `_thumbnail_id`. Failed attachments appear in skipped results and keep external references.
- Page caching: Settings → Reading `cacheSeconds` (0 = off). The web adds `s-maxage` to anonymous public GETs, re-reading the setting at most once a minute.
- Theme previews: `POST /api/v1/admin/themes/:id/preview` returns a signed 30-minute token; the web keeps it in the `cms_theme_preview` cookie and the public layout asks for that theme. Responses for visitors with session, unlock or preview cookies are never marked cacheable.
