# 사용자·역할·보호

상위 문서: [AGENTS.md](../../AGENTS.md)

- 캡차 설정을 저장할 때 활성 레지스트리에 없는 제공자는 거부합니다. 제공자를 바꾸면 새 비밀 값을 명시적으로 제출하지 않는 한 이전 비밀 값이 지워지므로, 검증을 켜기 전에 새 제공자의 비밀 값을 다시 입력해야 합니다. 제공자가 바뀌지 않았다면 생략된 비밀 값은 유지됩니다.
- 회원 가입이 닫혀 있으면 공개 가입은 플러그인 훅 이전에 중단됩니다. 그렇지 않으면 속도 제한/캡차 보호가 거부 전용 `user.registrationAllowed` 필터보다 먼저 실행됩니다. 모더레이터 알림 권한은 각 수신자의 사용자 id로 해석됩니다.

- 플러그인 역할 기본값은 등록되어 있는 동안 할당할 수 있으며, 저장된 관리자 정의가 기본값을 재정의합니다. 기본값을 철회해도 계정은 삭제되지 않습니다. 알 수 없는 역할/권한은 어떤 권한도 부여하지 않습니다.
- 비공개 프로필 메타데이터는 `profile-meta.<userId>` 설정에 저장되고 활성 필드 선언에 맞춰 검증되며, 공개 글쓴이 DTO에는 절대 추가되지 않습니다. 쓰기는 계정 삭제 및 개인정보 삭제 처리와 `users.lock`을 공유합니다. 개인정보 내보내기는 비활성 플러그인의 것까지 저장된 모든 메타데이터를 포함하며, 코어 개인정보 삭제 처리는 이를 원자적으로 삭제하고 익명화된 계정에 대한 이후의 쓰기를 거부합니다.
- 캡차 제공자 탐색은 ID와 레이블만 노출합니다. 공개 캡차 설정은 null 가능한 `widget: { script, scriptOrigin, render, origins, attributes, responseField }`를 노출합니다. 스크립트는 자격 증명이 없는 HTTPS URL(최대 2048자)이며, 선언에는 `data-*` 문자열 속성을 20개까지(이름 80자, 값 1024자) 허용하고, 응답 필드는 `[A-Za-z][A-Za-z0-9_-]*`와 일치해야 합니다(최대 100자). `render`는 마운트마다 `fn(container, { sitekey, callback })`로 호출되는 점으로 구분된 함수 경로(식별자 최대 4개, 최대 256자)이며, null이면 속성으로 자동 렌더링합니다. API는 자동 위젯에 대해 명시적으로 지정하지 않은 한 `data-sitekey`를 제공하며, 공개 속성 하나를 추가로 허용합니다. `origins`에는 HTTPS 출처를 최대 10개까지 넣을 수 있습니다(와일드카드 하위 도메인 허용, 경로 불가). API가 도출한 `scriptOrigin`과 문서화된 추가 호스트는 페이지 단위 CSP에만 추가합니다. 속성은 HTML이 아니라 DOM API로 적용하고, render 경로는 eval 없이 해석합니다. 코어 제공자도 같은 디스크립터를 사용합니다. 생략된 widget은 null이며 검증 우회가 아니고, 검증이 없거나 실패해 검증할 수 없으면 차단합니다. 제공자별 CSP 안내와 출처는 [확장 지점](../plugins/extension-points.md#사용자)에 있습니다.

- 역할은 WordPress 방식(`administrator`, `editor`, `author`, `contributor`)이며 권한(capability)을 부여합니다(`packages/sdk/src/capabilities.ts`, 순수 함수이며 브라우저에서 안전). 서비스는 `authorize(actor, capability)`로 권한을 확인하고, 라우트는 `session(app, capability)`에 권한을 전달할 수도 있습니다. 콘텐츠 규칙은 본인 항목(`content.create`/`content.publish`)과 다른 사람의 항목(`content.editOthers`)을 구분합니다. 관리자는 항상 최소 한 명이 남습니다(쓰기 직렬화). 글쓴이 선택지(`GET /api/v1/admin/users/authors`, `content.editOthers`)는 `{ id, name, slug }`이며, 슬러그는 관리자 콘텐츠 목록의 `author` 필터에 쓰입니다.
- 비밀번호 재설정과 초대는 일회용 토큰을 이메일로 보내며, API 토큰(`cms_pat_…`)은 세션처럼 인증되고 소유자가 목록을 보거나 폐기할 수 있습니다. 해시만 저장합니다.
- 관리자(`users.manage`)는 `POST /api/v1/admin/users/:id/password-reset`으로 재설정 링크를 보내고(캡차나 방문자 제한 없음, 관리자당 시간당 20회), `DELETE /api/v1/admin/users/:id/sessions`로 사용자를 모든 곳에서 로그아웃시킵니다(API 토큰은 유지). 일괄 역할 변경은 역할만 바꾸는 `PUT /api/v1/admin/users/:id/role`을 사용합니다. 사용자는 `GET /api/v1/auth/sessions`로 본인 세션(세션 다이제스트에서 파생된 불투명 id, 발급 및 만료 시각)을 조회하고 `DELETE /api/v1/auth/sessions/:id`로 하나를 로그아웃시킵니다. 사용자 지정 역할은 `DELETE /api/v1/admin/roles/:key?reassignTo=<role>`로 삭제하며, 이때 해당 사용자를 먼저 옮깁니다.
- 관리자 콘텐츠 목록은 `orderBy`(`updatedAt`, `publishedAt`, `title`, `author`, `commentCount`; SDK 허용 목록)와 `order`로 정렬하며 id를 동순위 기준으로 씁니다. 대시보드의 상자 순서와 숨긴 상자는 인증된 작성자를 따라 브라우저 간에 유지됩니다. `GET/PUT /api/v1/admin/dashboard-preferences`는 코어 설정의 `dashboard.<userId>`만 읽고 쓰며, 소유자는 세션에서 가져옵니다. 엄격한 SDK 계약은 `order`와 `hidden`만 받으며, 각각 1–200자의 식별자를 최대 100개까지 허용합니다. 개선된 화면 옵션 폼은 저장 성공/오류를 알려 주며, 이전의 공유 `cms_dashboard` 쿠키는 계정에 할당하지 않고 무시합니다. 플러그인 상자는 `GET /api/v1/admin/dashboard-widgets`에서 가져옵니다.
- `ProtectionService`는 로그인, 비밀번호 재설정, 댓글, 보호된 콘텐츠 잠금 해제를 보호합니다: DB 기반 속도 제한(`rate_limit_buckets`, 모든 인스턴스가 공유)과 캡차(Turnstile, hCaptcha, reCAPTCHA; 비밀 값은 봉인). 시도는 비밀번호, 메일, 댓글 처리 전에 카운터를 원자적으로 확보합니다. 증명되지 않은 방문자는 하나의 방문자 버킷을 공유하므로 API를 직접 호출해 계정 이름을 바꿔도 클라이언트 제한을 우회할 수 없습니다. `captcha_required`(403)는 폼에 캡차를 요청합니다.
- 비밀번호 변경과 재설정은 해시를 갱신하면서 재설정 링크, 다른 세션, API 토큰을 원자적으로 폐기합니다. 재설정 토큰은 비밀번호 해싱 전에 확인하고, 자격 증명 변경과 같은 트랜잭션에서 소비합니다.
- 설정에 저장되는 비밀 값(SMTP 비밀번호, 캡차 및 Meilisearch 키, 웹훅 비밀)은 `SecretBox`(AES-256-GCM, `CMS_SECRET_KEY`)로 봉인되며 반환되지 않습니다. 관리자 DTO는 `…Configured` 플래그만 노출합니다.
- 모든 웹훅, OIDC, Meilisearch, SMTP, 플러그인 업데이트 및 아바타 HTTP 연결은 DNS 결과를 검사하고 확인한 IP에 고정하는 공용 egress 정책을 통과합니다. 사설망·루프백·링크 로컬은 기본 차단하며 `egress.manage` 권한이 있는 관리자가 설정 → 외부 연결에서 서비스·호스트·포트·IP/CIDR을 함께 허용해야 합니다. 메타데이터·미지정·멀티캐스트·예약 주소는 허용 규칙으로도 열리지 않습니다. `CMS_EGRESS_ALLOWLIST`는 같은 규칙의 관리자 표시용 읽기 전용 재정의입니다. 업그레이드 때 이미 저장된 Meilisearch/SMTP 호스트가 사설 주소라면 현재 해석된 정확한 주소를 한 번만 초기 규칙으로 저장해 기존 로컬 설치를 유지합니다.
